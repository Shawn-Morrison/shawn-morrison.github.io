# 1. Project Approach 

**This project will be completed over a short development window of approximately 3–4 days. Due to the limited timeline and clearly defined scope, the approach will be structured but lightweight.**

## The project will follow four controlled phases:

**Planning – Finalize scope and identify risks.**

**Design & Content Drafting – Outline structure and draft page content.**

**Development – Build HTML pages and apply CSS styling.**

**Review & Refinement – Test functionality, revise documentation, and finalize repository.**

*-Because this is a small, static website, work will proceed sequentially with minor iteration as needed.*

# 2. Risk Analysis (TAME Framework)

**The following risks have been identified using the TAME framework from PMUPM Chapter 4.**

## Risk 1: Time Compression

* **Threat:** The short completion window may reduce time available for refinement.

* **Assumption:** All required components can be completed within a few focused work sessions.

* **Mitigation:**

    * Complete documentation drafts before polishing visual design.

    * Prioritize required deliverables over aesthetic enhancements.

    * Allocate specific time blocks for each phase.

* **Exposure:** *Moderate – Time pressure could impact quality if work is delayed.*

## Risk 2: Technical Errors in HTML/CSS

* **Threat:** Broken links, formatting inconsistencies, or syntax errors.

* **Assumption:** A two-page static site is manageable with existing skill level.

* **Mitigation:**

    * Test all navigation links.

    * Validate HTML structure.

    * Use one external stylesheet to ensure consistency.

* **Exposure:** *Low – Issues are easily identified and corrected.*

## Risk 3: Scope Creep

* **Threat:** Adding unnecessary features (extra pages, advanced styling, animations).

* **Assumption:** A simple, clean site meets all assignment requirements.

* **Mitigation:**

    * Follow the approved scope statement strictly.

    * Avoid adding functionality outside defined exclusions.

* **Exposure:** *Low – The scope is clearly limited and documented.*

## Risk 4: Documentation Misalignment

* **Threat:** Scope, plan, and final repository contents may not fully align.

* **Assumption:** Documentation will remain consistent through revisions.

* **Mitigation:**

    * Conduct a final alignment review before submission.

    * Cross-check deliverables against scope and rubric.

* **Exposure:** *Moderate – Misalignment could impact grading across multiple categories.*
